# Repository Index

## Purpose
Maintains a fast, searchable inverted index of all symbols, classes, methods, and configurations found by the Scanner. This allows the Context Resolver to instantly find where specific concepts are defined without rescanning the disk.

## Inputs
- `RawTopologyData` (JSON): From the Repository Scanner.

## Outputs
- `SearchableIndex` (Key-Value Store / JSON):
  ```json
  {
    "symbols": {
      "Invoice": ["src/domain/Invoice.ts"],
      "calculateTax": ["src/domain/Invoice.ts", "src/utils/tax.ts"]
    },
    "dependencies": {
      "express": ["src/api/server.ts", "package.json"]
    },
    "last_updated": "2026-07-01T12:00:00Z"
  }
  ```

## Algorithm Steps
1. **Data Ingestion**: Consume the `RawTopologyData` generated by the Scanner.
2. **Symbol Extraction**: For each file, extract all exported symbols (class names, function names, interfaces, enums, constants).
3. **Inverted Index Construction**: Map each symbol to the list of file paths where it is defined or heavily used.
4. **Dependency Indexing**: Map third-party dependencies (from package managers or import statements) to the files that use them.
5. **Persistence**: Serialize the index to disk (e.g., `.projectos/cache/index.json`) for fast loading on subsequent runs.

## Query Interface
- `findDefinition(symbol)`: Returns the primary file path defining the symbol.
- `findUsages(symbol)`: Returns all file paths importing or referencing the symbol.

## Update Strategy
- **Incremental**: Only update the index entries for files modified since `last_updated` based on filesystem timestamps.
- **Full Rebuild**: Triggered manually or if the cache is corrupted.

## Dependencies
- Repository Scanner.

## Edge Cases & Error Handling
- **Symbol Collisions**: If `User` is defined in multiple bounded contexts (e.g., `auth/User` and `billing/User`), the index must store the fully qualified path and prompt the Context Resolver for disambiguation when queried.
