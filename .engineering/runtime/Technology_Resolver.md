# Technology Resolver Engine

## Purpose
Dynamically loads language-specific and framework-specific rules from the Plugin Registry based on the project's technology stack.

## Inputs
- `TechStack` (YAML): From `config/stack.yaml`.
- `TaskPlan` (JSON): The current tasks.

## Outputs
- `ActiveTechPacks` (Array of Pack Objects): Contains the specific boilerplate, best practices, and anti-patterns for the frameworks in use.

## Algorithm Steps
1. **Stack Parsing**: Read `stack.yaml`. Extract languages (e.g., `python: 3.11`), frameworks (e.g., `fastapi`), and infrastructure (e.g., `docker`).
2. **Registry Lookup**: Search `.engineering/registry/packs/` for matching manifests.
3. **Dependency Resolution**: If the `fastapi` pack requires the `python` pack, ensure both are loaded.
4. **Context Injection**: Append the `best-practices.md` and `pitfalls.md` from the loaded packs to the `ContextPayload` generated by the Context Resolver.

## Edge Cases & Error Handling
- **Unknown Technology**: `stack.yaml` specifies `bun`, but no `bun` pack exists in the registry. Fallback: Fall back to generic `standards/backend.md` and emit a warning to the user to consider building a `bun` tech pack.
- **Version Mismatch**: `stack.yaml` specifies `react: 16`, but the React tech pack requires `react: >=18`. Fallback: Load the pack but prepend a bold warning that the AI's advice might use APIs incompatible with the older version.
